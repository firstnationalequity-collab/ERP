| 2026-11-17 | E-signature in two steps: `verifySignature`/`verifyWitness` re-check the password in their own transaction (a failure is committed, then `ESIGN_FAILED`), and `recordSignature` stores the row inside the business transaction. The verified proof is single-use, expires after 2 min, and can only be created by `core/esign` | A wrong password must count toward lockout (Q3) even though the action is rolled back; a signature cannot be replayed or forged | Agent (M1 task 5) |
| 2026-11-17 | Witness / countersign = a second person signs at the same terminal with their own username + password; must differ from the actor (`SEGREGATION_OF_DUTIES`); wrong password counts against the witness's account | QA witness for lot disposal (Q15) and QA countersign for role changes (Q1) | Agent (M1 task 5) |
| 2026-11-17 | `e_signatures` stores the signer's username and full name at signing time; append-only; SYSTEM can never sign | Printed name must stay correct after a rename (Part 11 §11.50) | Agent (M1 task 5) |

| 2026-11-17 | The transition engine itself locks the row and reads the current status (callers only say the target status); moves with permission `SYSTEM` are for background jobs only, and the SYSTEM actor can make no other move | No stale "from" status; jobs cannot approve or release anything | Agent (M1 task 5) |
