# M4 demo — QC (tasks 1–3)

Users: `demo.qc_analyst`, `demo.qc_manager`, `demo.storekeeper` (password = `DEV_DEMO_PASSWORD`). Before: `pnpm db:seed:demo-data`, then post a GRN for a QC-required item (demo/M3.md) so a lot sits in QUARANTINE. On the GRN line, typing expiry `06-2028` stores 30-06-2028 (month and year only = last day of the month).

## Steps
1. **demo.qc_analyst** → Quality control → Specifications → New version for the GRN's item; add Assay 98–102 % (assay), Water ≤ 0.5 % (water), Identification (text "Complies"); Submit.
2. **demo.qc_manager** → open it → Approve, e-sign (APPROVED). Expected: v1 APPROVED.
3. **demo.qc_analyst** → Sample queue → open the OPEN request. Expected: the three tests, and the location holding the lot.
4. Take sample: test quantity 2, retention 1. Expected: request SAMPLED, lot UNDER_TEST, spec v1 pinned; Stock shows the lot 3 lower; a QC_SAMPLE journal Dr 6400 / Cr 1310 at the lot cost.
5. Enter results: Assay 99.12345, Water 0.2, Identification "Concordant" + Complies → Save. Expected: all PASS; the lot stays UNDER_TEST.
6. **demo.qc_manager** → Results review → open the sample → Review, e-sign (REVIEWED). Expected: all results show "Reviewed: demo.qc_manager".
7. FG (after M6, or with a test FG lot): a failing assay on an FG lot. Expected: the lot goes to HOLD at once; a banner says QA decides.
8. **demo.qc_manager** → Lot disposition → open the lot. Expected: all tests PASS and reviewed; "Approval writes assay 99.1235 and water 0.2000".
9. Approve lot, e-sign (APPROVED). Expected: lot APPROVED, assay 99.1235 / water 0.2000 on the lot, sample request CLOSED, the decision listed with your name and reason; the lot can now be issued.
10. Second GRN lot: sample it, enter Assay 96 (FAIL), review, then Lot disposition → Reject lot, e-sign (REJECTED) with a reason. Expected: lot REJECTED; it can only be destroyed or returned to the vendor (with a QA witness).
11. Third GRN lot, not sampled: Lot disposition → filter Quarantine → open it → category Damaged container, description "Two drums dented, liner torn" → Reject lot, e-sign. Expected: lot REJECTED, its sample request CANCELLED, the decision shows the category.

## Must be refused
- Taking a sample for an item with no APPROVED spec → SPEC_NOT_APPROVED; demo.qc_manager entering results → 403.
- A second result for the same test → ALREADY_EXISTS; a reviewer who entered a result reviewing it → SEGREGATION_OF_DUTIES.
- Approving before every result is reviewed (QC_RESULTS_NOT_REVIEWED), with a test missing (QC_RESULTS_INCOMPLETE) or with a failed test (QC_TEST_FAILED); rejecting without a failed result and without a reason category + description → QC_REJECT_CATEGORY_REQUIRED (Reject stays disabled until both are filled).
- demo.qc_analyst, demo.qa_manager or demo.ceo approving or rejecting a lot → 403; approving a material lot on HOLD → only QA lifts a hold.
- Approving or rejecting a finished-goods lot → FG_LOT_QA_DECIDES; issuing a REJECTED lot → LOT_NOT_APPROVED.
