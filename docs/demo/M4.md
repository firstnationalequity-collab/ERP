# M4 demo — QC (tasks 1–2)

Users: `demo.qc_analyst`, `demo.qc_manager` (password = `DEV_DEMO_PASSWORD`). Before: `pnpm db:seed:demo-data`, then post a GRN for a QC-required item (demo/M3.md) so a lot sits in QUARANTINE.

## Steps
1. **demo.qc_analyst** → Quality control → Specifications → New version for the GRN's item; add Assay 98–102 % (assay), Water ≤ 0.5 % (water), Identification (text "Complies"); Submit.
2. **demo.qc_manager** → open it → Approve, e-sign (APPROVED). Expected: v1 APPROVED.
3. **demo.qc_analyst** → Sample queue → open the OPEN request. Expected: the three tests, and the location holding the lot.
4. Take sample: test quantity 2, retention 1. Expected: request SAMPLED, lot UNDER_TEST, spec v1 pinned; Stock shows the lot 3 lower; a QC_SAMPLE journal Dr 6400 / Cr 1310 at the lot cost.
5. Enter results: Assay 99.4, Water 0.6, Identification "Concordant" + Complies → Save. Expected: Water FAIL (computed), others PASS; the lot stays UNDER_TEST (material lot: QC Manager decides in task 3).
6. **demo.qc_manager** → Results review → open the sample → Review, e-sign (REVIEWED). Expected: all results show "Reviewed: demo.qc_manager"; the sample leaves the review queue.
7. FG (after M6, or with a test FG lot): a failing assay on an FG lot. Expected: the lot goes to HOLD at once; a banner says QA decides.

## Must be refused
- Taking a sample for an item with no APPROVED spec → SPEC_NOT_APPROVED; nothing changes.
- demo.qc_manager taking a sample or entering results → 403 (QC Analyst key only).
- Entering a second result for the same test → ALREADY_EXISTS (results are never edited; re-test comes in task 4).
- A reviewer who entered any of the results reviewing them → SEGREGATION_OF_DUTIES.
- Issuing or reserving an APPROVED lot whose expiry or retest date has passed (before the nightly job) → LOT_EXPIRED / LOT_RETEST_DUE.
