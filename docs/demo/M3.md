# M3 demo: PO → goods received → landed cost → vendor invoice → payment → reversals, debit notes (tasks 3–5b)

Users: `demo.purchase_officer`, `demo.purchase_manager`, `demo.storekeeper`, `demo.finance_manager`, `demo.warehouse_manager`, `demo.accountant`, `demo.ap_officer`, `demo.qa_manager` (password = `DEV_DEMO_PASSWORD` in `.env`).
Before: `docker compose up -d db`, `pnpm db:migrate`, then **`pnpm db:seed:demo-data`** (development only, same guard as `db:seed:dev`, which it runs first). Through the normal services, as the demo users, it creates: 10 items `DM-…` (2 API, 3 excipients, 3 packing, 2 FG), ACTIVE; vendors DM-V-CHEM (PKR, 30 days), DM-V-PACK (PKR), DM-V-IMP (CN, USD), each with QA-approved sources (demo evidence attached); customers DM-C-001/002; warehouse DM-WH with QUAR, APPR, REJ, RET (returns area); product DM-FG-001 with an APPROVED formula; today's USD rate (demo value 281.25, not SBP); PO-…00001 local excipients APPROVED, PO-…00002 import API (USD 3,100) PENDING_APPROVAL with the Finance Manager. Running it again changes nothing (only sign-ins are recorded; a later day adds that day's USD rate). Still add by hand: vendor "Pakistan Customs", a SPARE item.
In the steps below, "the RM item" can be DM-EXC-001 from DM-V-CHEM; the USD vendor is DM-V-IMP.

## Steps
1. **Purchase officer** → Purchase orders → New: LOCAL, RM 100 KG at 50.125 → Save, Submit. **Purchase manager** → My approvals → Approve (password). Expected: APPROVED.
2. **Storekeeper** → Goods received → Receive against the PO: qty 60, containers 3, batch, expiry, QUAR → Save draft.
3. **Purchase officer** opens the draft GRN → Add a charge: FREIGHT 600 by value; IMPORT_ST 500 billed by Pakistan Customs. Try IMPORT_ST in USD → refused (PKR only).
4. **Storekeeper** → Post. Expected: lot ML26-… QUARANTINE, QC sample OPEN, both charges POSTED; lot cost (3,007.50 + 600) ÷ 60 = 60.125000; labels print.
5. **Purchase officer** → a SPARE PO 10 at 100, received and posted → Add a later bill INSURANCE 1,000 → Post. Then Correct 400; **Finance manager** → Approve and post.
6. **Finance manager** → Landed costs → Charge types: CD, ACD, RD, IMPORT_ST, IMPORT_IT show "PKR only"; enter the USD rates for the PO, GRN and invoice dates.
7. **Accountant** → Vendor invoices → Enter invoice → Goods, the step-1 PO: GRN line 60 at 50.50, sales tax ST-18 → Save draft → Post.
   Expected: POSTED (0.75% within 2%); journal Dr GRNI 3,007.50, Dr price variance 22.50, Dr input tax / Cr payables; drawer shows the match "OK".
8. **Accountant**: the SPARE PO, 10 at 120 → Post. Expected: MATCH_EXCEPTION (price 20%). **Finance manager** → Release and post (password + reason) → POSTED.
9. **Accountant** → Enter invoice → Charges → Pakistan Customs: IMPORT_ST 500 → Post. Expected: Dr landed-cost clearing / Cr payables (Customs).
10. USD PO 10 at 10 received at the GRN rate; invoice 10 at 10.10 on a later rate. Expected: GRNI at the GRN value, exchange gain/loss for the rate change, price variance for 0.10.
11. **AP officer** → Vendor payments → Draft payment → local vendor → settle the step-7 invoice → Save. Submit. Expected: WHT section shown; a placeholder rate → refused.
12. **Finance manager** → Masters → Tax codes → WHT code: non-filer rate, base (incl./excl. sales tax), switch off "not confirmed", tick "Base confirmed". **AP officer** Submit; **Finance manager** → My approvals → Approve (a vendor whose filer check is over 30 days old: tick the warning); **AP officer** → Post, entering the cheque / bank reference.
    Expected: filer rate for an ATL vendor, non-filer rate otherwise, on the code's base; Dr payables / Cr bank (net) + WHT payable; the invoice is no longer open. A foreign payment asks for the PKR paid; the difference is exchange gain/loss.
13. Vendor ledger: pick the vendor → invoice credit, payment debit, running balance. AP ageing: as of 30 days after the due date → amounts in 1–30.
14. Purchase orders: a PO fully received and fully billed shows CLOSED.
15. **Finance manager** → Vendor invoices → a posted, unpaid invoice → Reverse (password + reason). Expected: REVERSED, journal mirrored today, PO back to RECEIVED, the GRN line billable again, the vendor number free.
16. **Finance manager** → Vendor payments → a posted payment → Reverse ("cheque bounced"). Expected: REVERSED; the invoice is open again; the ledger shows both entries.
17. **Accountant** → Debit notes → Draft → posted invoice → Price claim 50 on a line with ST-18 → Submit; **Finance manager** approves; **Accountant** → Post. Expected: Dr payables 59 / Cr price variance 50 / Cr input tax 9; invoice open, ledger and ageing reduced. Short supply: only the quantity billed beyond what was received.
18. Return to vendor (needs a lot QC REJECTED; the QC screen comes in M4): note with the quantity → approved → **Warehouse manager** → Post return with **demo.qa_manager** as witness. Expected: stock out, Dr payables / Cr inventory + variance + input tax; lot RETURNED when empty.
19. **Finance manager** → Debit notes → a posted note → Reverse (password + reason; for a return, the QA witness signs in the same box). Expected: REVERSED, journal mirrored today, the invoice open again (then the invoice itself can be reversed); a return puts the quantity back into the REJECTED lot.

## Must be refused
- Receive 103 on a 100 line → **OVER_RECEIPT**; the PO's creator or approver posts its GRN → **SEGREGATION_OF_DUTIES**; blocked source → **AVL_NOT_APPROVED**.
- CD / IMPORT_ST in USD, or GD amounts in USD → **CURRENCY_NOT_ALLOWED**. A correction larger than what is left or below what was billed → **CORRECTION_EXCEEDS_CHARGE**.
- The Accountant releases a MATCH_EXCEPTION invoice → 403; one person with both roles releases their own → **SEGREGATION_OF_DUTIES**; the same vendor bill number twice → **ALREADY_EXISTS**.
- A charges invoice above what is open on the charge → **AMOUNT_EXCEEDS_OPEN**; a payment above what is open → **AMOUNT_EXCEEDS_OPEN**.
- The AP officer approves their own payment → **SEGREGATION_OF_DUTIES**; WHT on a placeholder rate → **TAX_RATE_NOT_CONFIRMED**.
- Reverse a GRN that is on a vendor invoice → **IN_USE**; after a lot moved → **GRN_LOTS_IN_USE**. Edit a posted invoice or payment → **RECORD_LOCKED**.
- Change an active vendor's WHT section without a Purchase Manager countersign → **COUNTERSIGN_REQUIRED**.
- Reverse a paid or debited invoice → **IN_USE**; the Accountant reverses → 403; post a payment without a reference → refused; approve a stale-filer payment without the tick → **ACKNOWLEDGEMENT_REQUIRED**.
- A debit note above what is open → **AMOUNT_EXCEEDS_OPEN**; a return of a lot not REJECTED → **INVALID_TRANSITION**; a return without the QA witness → **WITNESS_REQUIRED**. Reverse an invoice with a debit note in force → **IN_USE**; reverse the note of a lot already RETURNED → **LOT_RETURN_NOT_REVERSIBLE**.
